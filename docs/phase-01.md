# Phase 1 — Core, Platform, 메인 루프

> 이 단계 당시 상태를 기준으로 썼음. 지금 엔진의 전체 기능은 [Architecture.md](Architecture.md)에 따로 정리했음.

## 왜 이렇게 설계했음

렌더러보다 먼저 창·입력·시간 규칙이 안정적이어야 뒤에서 물리나 카메라를 붙일 수 있다고 봤음. 그래서 `Window`가 Win32 자원을 소유하고, `RunApplication`이 실행 순서와 종료를 관리하도록 나눴음. Win32 헤더가 공개 API에 퍼지지 않게 Window는 pImpl로 감쌌음.

## 구현하면서 정한 규칙

- 고정 업데이트를 60 Hz로 잡았음. 한 프레임에서 최대 8 tick만 처리하고, 0.25초를 넘는 긴 경과 시간은 잘라서 종료 로그에 버린 시간을 기록했음. 창을 드래그한 뒤 물리 tick이 몰아서 실행되는 상황을 피하려는 선택이었음.
- `Pressed/Released`는 첫 고정 tick까지 보관하고 그 tick 뒤에 소비하도록 했음. `Held`는 현재 상태를 나타내게 했음. OS 키 자동 반복을 새 Pressed로 세지 않았음.
- 창이 비활성화되거나 최소화되면 입력과 시간 누적을 초기화했음. 포커스가 돌아왔을 때 이전 입력이 남아 움직이지 않도록 했음.
- `OnStart`가 성공한 뒤에는 예외가 나도 `OnStop`을 한 번 호출하게 했음. `OnStart` 자체가 실패한 경우에는 RAII가 자원 정리를 맡음.

## 확인한 것과 남은 것

Core 테스트에서 짧은 탭, 자동 반복, tick 사이 입력 보존, 긴 stall, 120회의 1/120초 입력이 60 tick이 되는지 확인했음. 숨겨진 Win32 창의 생성·해제, resize, focus, 최소화, 종료와 콜백 순서도 검사했음. Phase 1 화면은 GDI로 상태만 보여 줬고 DirectX 렌더링은 없었음.

빠른 여러 탭은 한 tick의 bool 상태로 합쳐짐. 텍스트 입력, 게임패드, Raw Input, 커서 잠금과 다중 DPI 실측도 이 단계 범위가 아니었음. 다음 Phase에서 이 루프 위에 D3D11을 올리기로 했음.
